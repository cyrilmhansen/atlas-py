[L1] histogram sort
[L2] histogram sort
[L3] (algorithm)
[L4] Definition:
[L5] An efficient 3-pass refinement of a
[L6] bucket sort
[L7] algorithm. The first pass counts the number of items for each bucket in an auxiliary
[L8] array
[L9] , and then makes a running total so each auxiliary entry is the number of preceding items. The second pass puts each item in its proper bucket according to the auxiliary entry for the
[L10] key
[L11] of that item. The last pass sorts each bucket.
[L12] Also known as
[L13] interpolation sort.
[L14] Generalization
[L15] (I am a kind of ...)
[L16] bucket sort
[L17] .
[L18] Specialization
[L19] (... is a kind of me.)
[L20] counting sort
[L21] .
[L22] See also
[L23] American flag sort
[L24] .
[L25] Note:
[L26] A bucket sort uses fixed-size buckets. A histogram sort sets up buckets of exactly the right size in a first pass. A counting sort is a histogram sort with one bucket per possible key value.
[L27] The following note is due to Richard Harter,
[L28] [email protected]
[L29] , http://www.tiac.net/users/cri/, 8 January 2001, and is used by permission.
[L30] The run time is effectively
[L31] O(n log log n)
[L32] . Let S be the data set to be sorted, where n=|S|. R is an approximate rank function to sort the data into n bins. R has the following properties.
[L33] R is an integer valued function into [0, n-1].
[L34] 0 ≤ R(x) ≤ n-1 for x in S.
[L35] For some x,y in S, R(x)=0 and R(y)=n-1.
[L36] x < y implies R(x) ≤ R(y) for x,y in S.
[L37] Each bin then has, on average, 1 entry. Under some rather broad assumptions the number of entries in a bin will be Poisson distributed whence the observation that the sort is O(n log log n).
[L38] Let T be the final array for the sorted data. Allocate an auxiliary integer array H indexed 0 … n-1. We make one pass through the data to count the number of items in each bin, recording the counts in H. The array H is then converted into a cumulative array so each entry in H specifies the beginning bin position of the bin contents in T. We then make a second pass through the data. We copy each item x in S from S to T at H(R(x)), then increment H(R(x)) so the next item in the bin goes in the next location in T. (The bin number R(x) could be saved in still another auxiliary array to trade off memory for computation.)
[L39] For numeric data, there is a simple R function that works very well: Let min, max be the minimum and maximum of S. Then R(x) = n*(x - min)/(max-min).
[L40] This uses quite a bit of extra memory. For large data sets, there could be slow downs because of page faults. For large n it is more efficient to bound the number of bins.
